# MASTER BUILD PROMPT — Convert Existing Roofing Website Into a Client-Editable CMS Platform

## PROJECT

Existing website:

https://thisismynamenot.github.io/Claude/

Existing source is hosted in GitHub.

The current website design, visual identity, layout quality, animations, typography, spacing, responsiveness, content hierarchy, project presentation, and overall premium appearance are already approved.

The purpose of this task is NOT to redesign the website.

The purpose is to transform the existing static website into a professional, production-ready, client-editable website system while preserving the current frontend design as closely as technically possible.

---

# PRIMARY OBJECTIVE

Convert the existing website into:

Astro + TinaCMS + GitHub + Cloudinary + Cloudflare Workers

The final website must allow a non-technical client to manage the website without editing code.

The client must be able to:

- add projects
- edit projects
- delete/archive projects
- upload images
- create project galleries
- edit page titles
- edit paragraphs
- edit buttons
- edit links
- change contact information
- edit services
- edit company information
- change homepage content
- select featured projects
- reorder content
- add/remove predefined sections
- update SEO information
- publish changes safely

The client must never need to open GitHub or edit HTML/Markdown/code manually.

---

# NON-NEGOTIABLE REQUIREMENT

## Preserve the existing design.

Do NOT turn this into:

- a generic Astro starter
- a generic CMS theme
- a Tailwind template
- a SaaS-looking site
- a WordPress-looking site
- a generic construction-company template

Reproduce the existing website faithfully.

The CMS must sit behind the design, not dictate the design.

Think of this project as:

Existing approved frontend + professional content architecture.

Not:

New CMS template using the old content.

Use:

# PRODUCTION DEPLOYMENT ARCHITECTURE

The target publishing architecture should be:

Client edits content in TinaCMS
↓
Content changes are committed/saved through Git-backed content
↓
GitHub remains the source of truth
↓
Cloudflare automatically builds/deploys the production site
↓
The live domain is updated

Target:

GitHub
Source code + content history
        │
        ▼
Cloudflare Workers
        │
        ▼
Production website
        │
        ├── TinaCMS editing
        ├── Cloudinary media
        └── Forms/API functionality

The client must not interact with GitHub, Cloudflare, Astro, Tina internals, or Cloudinary directly during normal editing.
